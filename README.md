# 별무리 AI 문서

공개 문서 사이트의 화면 정본은 Open CoDesign 시안에서 가져온 `src/components/App.jsx`다. Astro의 React 통합으로 해당 화면을 직접 렌더링한다.

메인 문서의 정본은 `src/content/docs/index.md`다. 메모리 문서 두 편은 `src/content/docs/memory/`, 기술 시리즈는 `src/content/docs/technical-series/`에 둔다. Astro가 연결된 Markdown의 본문과 제목을 읽어 화면에 전달한다. `drafts/`의 검수용 자료는 화면에 연결하지 않는다.

## Content Roles

메인은 포트폴리오의 입구이고, 상세 페이지는 기술 문서다. 메인에서 대표 문제 해결을 요약하고 관련 기술 문서로 직접 연결한다. 별도의 포트폴리오 사례 상세 페이지를 만들어 기술 문서와 중복시키지 않는다.

- 메인은 프로젝트 소개, 담당 범위, 대표 문제와 선택, 결과를 설명한다. 본인의 기여를 설명할 때는 "저는 … 개발했습니다"와 같은 1인칭을 사용할 수 있다.
- 상세는 현재 시스템의 동작, 설계 이유, 인터페이스, 상태 전이, 실패 처리와 평가 방법을 설명한다. "세션은 … 유지합니다"처럼 구성 요소를 주어로 쓴다. 개인의 성장, 기여 강조, 개발 회고로 본문을 구성하지 않는다.
- 설계 이유와 대안의 비용은 상세에도 포함한다. "제가 고민해서 선택했습니다" 대신 어떤 조건 때문에 해당 설계가 필요한지 설명한다. 과거 비교 실험은 평가 절에 조건과 결과를 모아 제시한다.
- 기존 문서와 주제가 겹치면 해당 문서를 보완하거나 하위 기술 문서로 연결한다. 같은 구현을 포트폴리오용과 문서용으로 두 번 설명하지 않는다.

## Writing Conventions

- 문서 제목, 소제목과 도표 제목은 영어로 쓰고, 설명 본문은 한국어 존댓말로 쓴다. 사이트와 프로젝트의 고유 이름인 "별무리 AI"는 유지한다.
- 본문은 독자가 동작과 설계 이유를 이해하도록 쓴다. 작성자용 검수 지시, 후속 작업 목록과 근거 수집 메모는 초안 README에 둔다.
- 평가 결과에는 환경, 비교 조건과 지표를 가까이 표시한다. 해석에 필요한 한계는 해당 결과 옆에 한 번 설명하고, 문단마다 일반적인 주의사항을 반복하지 않는다.
- 미측정 항목은 평가 표에 "미측정"으로 표시할 수 있다. 입력 접두부 일치량과 실제 KV 적중 수처럼 다른 지표의 정의는 계측 절에서 설명한다.
- 사용자 수정본을 먼저 읽고 요청 범위만 수정한다. 제목 변경 요청으로 본문을 다시 쓰거나, 초안 요청으로 사이트를 게시하지 않는다.

## Draft Review

작성 전에 이 README와 `AGENTS.md`를 읽는다. 검토할 때는 메인과 상세의 역할이 분리됐는지, 제목이 영어인지, 수치의 조건이 명확한지, 기존 문서와 중복되는지 확인한다. 초안은 `drafts/`에 두고, 사이트에 반영할 때 관련 문서와 도표의 설명도 같은 구현 기준으로 맞춘다.
