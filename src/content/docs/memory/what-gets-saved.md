사용자가 차를 좋아한다고 말한 것과 차를 좋아하느냐고 물은 것은 다릅니다. 질문을 취향으로 저장하면 다음 대화에서 사용자가 하지 않은 말을 기억하게 됩니다. PetAI는 대화 답변을 만들 때, 사용자의 발화에 기억할 만한 사실이 있는지도 함께 판단합니다.

## The decision

판정 대상은 두 가지입니다. `P`는 현재의 지속적인 취향이나 선택 방침이고, `E`는 사용자가 완료했다고 말한 행동이나 경험입니다. 두 값은 각각 판단합니다.

| 발화에 포함된 정보 | P | E |
| --- | ---: | ---: |
| 완료한 경험과 현재의 지속적인 취향 | 1 | 1 |
| 사용자가 완료한 행동만 포함 | 0 | 1 |
| 타인의 취향만 포함 | 0 | 0 |

질문, 가정, 인용문과 타인의 사실을 사용자의 경험으로 취급하지 않도록 지시합니다. 한 발화에 타인의 이야기와 사용자의 경험이 섞여 있으면 사용자에 관한 부분을 판정합니다. 저장할 때는 판정에 사용한 절만 추출하지 않고 발화 원문을 기록합니다.

## The write path

언어 모델은 답변을 생성하면서 첫 줄에 `save(P=X,E=Y)` 형식의 판정값을 씁니다. 그다음 줄부터 사용자에게 보여 줄 답변을 씁니다. 앱은 첫 줄을 화면에서 숨기고 답변만 전달합니다.

저장은 형식이 맞는 판정값과 실제 답변이 있고, Unity의 표시 결과 확정을 거쳐 일반 대화가 완료됐을 때 진행됩니다. 출력 필터가 답변을 차단하거나 요청을 취소하면 이 저장 경로로 진행하지 않습니다. `P=0,E=0`이거나 판정값이 없거나 형식이 잘못되면 저장하지 않습니다. 판정값만 나오고 답변이 비어 있으면 답변 생성만 한 번 다시 시도합니다. 이때 새로 만든 답변에서 저장 판정을 가져오지는 않습니다. 요청 식별자도 확인해 같은 요청에서 기억 쓰기가 두 번 일어나지 않도록 합니다.

저장하기로 한 발화는 사용자의 원문 그대로 앱 내부 저장소에 기록합니다. `P`와 `E` 판정, 시각 정보, 검색에 사용할 임베딩도 함께 남깁니다. 사용자와 타인에 관한 내용이 섞인 발화는 두 내용이 모두 원문에 남습니다. 답변 생성이 끝난 뒤 쓰기에 실패해도 이미 만든 답변은 유지하고 오류를 기록합니다.

## Atomic writes

기억 엔진은 판정과 임베딩 계산을 끝낸 뒤 SQLite 쓰기를 시작합니다. 원문 행, 판정, 기억 항목과 라벨, 임베딩은 하나의 트랜잭션에 묶습니다. 모든 쓰기가 성공하면 커밋하고, 중간 쓰기나 커밋이 실패하면 롤백합니다. 임베딩 계산에 실패했을 때 원문 행만 남는 일을 막기 위한 순서입니다.

트랜잭션 내부에는 비동기 대기가 없습니다. 롤백 자체가 실패하면 해당 연결을 닫고 오류를 반환합니다.

## Why the gate is strict

형식이 불확실한 판정값으로 원문을 저장하지 않도록, 현재 제품은 판정값을 복구하거나 보충하지 않고 저장을 건너뜁니다. 이 선택으로 잘못된 판정값에 따른 저장은 줄일 수 있지만, 저장할 만한 발화도 놓칠 수 있습니다.

저장 단위에도 제한이 있습니다. 현재 기억은 발화 원문입니다. 한 문장에 오래된 취향과 새 취향이 함께 있더라도 둘을 갱신 가능한 사실 두 개로 분리하지 않습니다. 따라서 `P`와 `E` 판정이 맞았다는 사실만으로 나중에 현재 상태를 정확히 답할 수 있다고 볼 수 없습니다.

원자적 쓰기는 새 저장 요청의 정합성을 보장하기 위한 처리이며, 과거에 남은 불완전한 행을 정리하지는 않습니다. 저장 정합성 테스트는 계산 실패, 단계별 쓰기 실패, 커밋·롤백 실패와 계산 중 취소를 주입합니다. 저장소를 다시 열어 기존 기억이 유지되고 불완전한 행이 추가되지 않았는지 확인합니다. 동시 쓰기와 중복 요청도 별도로 검사합니다. P·E 판정의 정확도는 이 검증과 별도로 측정해야 합니다.
