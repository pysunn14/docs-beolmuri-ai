title: How memories are retrieved
description: PetAI가 저장된 발화를 다시 찾고 모델 입력에 넣는 방법
---

저장한 발화를 다음 대화에 전부 붙일 수는 없습니다. 현재 질문과 관련 있는 기록을 고르는 검색 단계가 필요합니다. PetAI는 사용자의 질문과 저장된 발화를 각각 EmbeddingGemma 벡터로 바꾸고 유사도를 비교합니다.

## The retrieval path

검색 대상은 현재 사용자와 캐릭터 범위에 속한 활성 기억입니다. 앱은 질문의 임베딩을 만든 뒤, 저장 당시 만든 발화 임베딩과 코사인 유사도를 계산합니다. 현재 제품 설정은 유사도 `0.3` 이상에서 상위 10건을 요청합니다. 점수가 같으면 더 최근에 기록된 발화를 앞에 두고, 같은 문구가 중복되면 한 건만 남깁니다. 표현이 다른 두 문장이 같은 사실을 말하는지는 이 단계에서 판단하지 않습니다.

```text
현재 질문
  → 질문 임베딩
  → 같은 사용자·캐릭터의 활성 기억과 유사도 비교
  → 점수순 정렬, 동일 문구 제거, 상위 10건
  → 길이 예산 안에서 모델 입력에 추가
```

현재 구현은 이 범위의 후보 임베딩을 읽어 하나씩 비교합니다. 별도 근사 최근접 검색 인덱스는 사용하지 않습니다. 기억이 많아졌을 때 검색 시간과 메모리 사용량이 어떻게 변하는지는 실제 기기에서 따로 측정해야 합니다.

## What the model receives

검색 결과는 순서대로 모델 입력에 들어갑니다. 앱은 각 기억의 원문을 넣으며, 현재 질문과 관련 없는 기억은 무시하라고 모델에 지시합니다. 검색 결과가 없거나 검색에 실패하면 질문만으로 대화를 계속합니다.

현재 설정의 기억 입력 예산은 `10,000`이지만, 정확히 1만 토큰을 세는 값은 아닙니다. 구현은 UTF-8 바이트 수로 길이를 계산합니다. 예산을 넘는 기억은 건너뛰고 다음 후보를 확인합니다. 검색 상위 10건이 모두 모델에 들어간다는 보장은 없습니다.

기억을 저장할 때 기록한 시각도 현재 모델 입력에는 넣지 않습니다. 원문에 “예전에는”이나 “이제는” 같은 표현이 있으면 모델이 읽을 수 있지만, 기록 시각을 근거로 두 발화의 순서를 판단할 수는 없습니다.

## What the benchmark measures

EdgeMemBench v0는 관련 기억 검색 92건, 시간에 따라 달라진 사실 검색 72건, 필요한 기억이 없을 때의 기권 30건을 구분합니다. 이 세 영역은 저장 판정을 거치지 않습니다. 평가용 대화 기록을 이미 저장된 기억처럼 주입한 뒤 검색을 측정합니다. 따라서 이 결과는 대화 입력부터 저장, 검색, 답변까지 이어지는 제품 전체의 정확도가 아닙니다.

시간 관련 영역에서는 검토를 거쳐 점수에 포함한 69건을 대상으로 Dense 검색의 정답 근거 Hit@1이 `33.33%`였습니다. 모든 기록에 최신 시각을 우선하는 연구용 재정렬을 적용하면 `40.58%`가 되었지만, 원래 맞던 2건은 틀리게 바뀌었습니다. 이 재정렬은 제품에 들어가 있지 않습니다.

이 실패에는 두 종류가 섞여 있습니다. 최근에 기록한 문장이 질문에 필요한 현재 상태를 말하지 않을 수 있고, 문장을 저장한 시각이 문장 속 사건의 시각과 같지도 않습니다. 검색 순서만 바꾸어 두 문제를 해결했다고 주장할 수 없습니다.

## Current limits

유사도 하한 `0.3`과 상위 10건은 현재 제품 설정입니다. 독립적인 보정 자료에서 최적값으로 확정한 수치는 아닙니다. 유사도가 낮은 기억을 빼는 것과, 기억이 없을 때 모델이 모른다고 답하는 것도 서로 다른 문제입니다. EdgeMemBench의 검색 러너는 기억의 순위를 평가하며 최종 답변의 정확도까지 측정하지 않습니다.

현재 검색 방식은 관련 발화를 찾을 수 있어도, 서로 충돌하는 과거와 현재의 사실 중 어느 쪽이 답인지 항상 고르지는 못합니다. 시간 정보를 모델에 전달하는 방법과 기권 기준, 아이폰에서의 검색 자원 사용량은 별도로 확인해야 합니다.
