Gemma 4 E2B 모델 파일에는 여러 토큰을 미리 예측하는 MTP 기능이 들어 있습니다. 별무리의 iOS 대화 경로는 CPU에서 캐릭터의 자유 대화를 생성합니다. 같은 모델과 런타임에서 MTP 설정만 바꾼 맥 실험에서 고정 길이 벤치마크는 빨라졌고, 자유 대화는 느려졌습니다. 대화 경로의 기본 설정은 MTP 끔으로 두었습니다.

## Why the workload matters

MTP는 초안 작성기가 다음 토큰들을 먼저 제안하고, 주 모델이 제안을 확인하는 방식으로 생성 작업을 줄입니다. 제안이 자주 받아들여지면 한 번의 확인으로 여러 토큰을 진행할 수 있습니다. 제안이 잘 맞지 않으면 초안 작성과 확인에 쓴 비용이 남습니다.

[Google의 Gemma 4 안내](https://developers.google.com/edge/litert-lm/models/gemma-4)는 E2B의 CPU 실행에서 재작성, 요약, 코딩과 자유 생성의 MTP 효과가 다를 수 있다고 설명합니다. 그래서 고정 길이 벤치마크와 캐릭터 대화를 나누어 측정했습니다.

## Measurement setup

2026년 9월 29일, M5 Pro 맥에서 동일한 Gemma 4 E2B 모바일 양자화 파일과 LiteRT-LM 0.17.1을 사용했습니다. 컨텍스트 용량은 4,096토큰으로 설정하고 CPU 4스레드와 GPU를 각각 실행했습니다. 각 조건은 별도 프로세스에서 예열한 뒤 두 차례 측정했습니다. 대화 실험은 생각 모드를 끄고 탐욕적 생성으로 실행했으며, 짧은 일상 대화와 긴 캐릭터 자유 대화를 각각 두 차례 생성했습니다. MTP 이외의 모델과 생성 설정은 같은 조건으로 유지했습니다.

고정 길이 벤치마크는 512토큰을 입력하고 최대 256토큰 생성을 요청했습니다. 대화 실험에서 처리한 입력은 짧은 질문 66토큰, 긴 질문 104토큰이었습니다. 4,096토큰은 처리한 입력 길이가 아니라 설정한 컨텍스트 용량입니다. 생성 속도는 LiteRT-LM의 보고값, 메모리는 모델 로드 전 대비 맥 프로세스의 최고 `phys_footprint` 증가량입니다. 아래 값은 각 조건에서 두 회차의 중앙값이며, [검수용 측정 자료](evidence/mtp-mac-20260929.json)에 회차별 수치를 남겼습니다.

## Results

고정 길이 벤치마크의 생성 속도는 MTP를 켰을 때 CPU에서 1.81배, GPU에서 1.89배였습니다. 같은 모델로 긴 캐릭터 대화를 생성하자 CPU에서는 반대 결과가 나왔습니다.

| 작업과 지표 | CPU MTP 끔 | CPU MTP 켬 | GPU MTP 끔 | GPU MTP 켬 |
| --- | ---: | ---: | ---: | ---: |
| 고정 길이 생성 속도, 토큰/초 | 31.71 | 57.47 | 104.51 | 197.06 |
| 긴 자유 대화 생성 속도, 토큰/초 | 39.17 | 25.88 | 123.62 | 120.26 |
| 긴 자유 대화 응답 완료 시간, 초 | 6.80 | 10.23 | 2.11 | 2.17 |

CPU의 짧은 일상 대화에서도 생성 속도는 35.48토큰/초에서 23.63토큰/초로 떨어졌습니다. 긴 대화에서 CPU 응답 완료 시간은 약 3.43초 늘었고, GPU의 긴 대화 응답 시간은 두 조건이 비슷했습니다.

LiteRT-LM 로그에 기록된 `MTP Drafter - Success rate`는 고정 길이 입력에서 CPU 94.5%, GPU 96.5%였고, 두 대화 문항을 합친 실행에서는 각각 20.0%, 23.6%였습니다. 초안 토큰의 성공률이 낮아진 대화에서 생성 속도도 함께 떨어졌습니다.

CPU 대화 실행의 프로세스 메모리 증가량은 MTP 끔 0.969GiB, 켬 1.723GiB로 측정됐습니다. MTP를 켠 조건이 0.754GiB 더 높았습니다.

별무리의 CPU 자유 대화 경로는 응답 시간과 메모리 사용량을 기준으로 MTP 끔을 기본값으로 둡니다.
