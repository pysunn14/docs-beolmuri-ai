---

같은 모델 파일을 사용해도 실행 환경과 입력 구성에 따라 결과가 달라질 수 있습니다. 실험의 결론을 제품에 적용하려면 무엇을 공유하고 무엇이 다른지 먼저 정리해야 합니다.

현재 저장소에는 Swift 제품 코드를 사용하는 Mac 평가 실행부와 iOS 앱 런타임이 있습니다. 입력 구성 코드를 공유하는 부분이 있어도 전체 실행 환경이 같지는 않습니다.

## Shared and different conditions

| 항목 | Mac 평가 실행부 | iOS 앱 경로 |
| --- | --- | --- |
| 입력 구성 | 공유 Swift 코드를 호출합니다. | Swift 브릿지에서 구성합니다. |
| 생성 백엔드 | Mac 평가 실행부는 GPU를 사용합니다. | iOS 앱 런타임은 CPU로 설정되어 있습니다. |
| 장면 선택 | 해당 일관성 평가에서는 일반 분류로 고정합니다. | 현재 발화로 장면을 분류합니다. |
| 기억 | 실험에 지정한 고정 결과를 주입할 수 있습니다. | 실제 저장소에서 현재 질문으로 검색합니다. |
| 최근 대화 | 고정한 이력을 실험 입력으로 넣을 수 있습니다. | 사용 중 완성된 대화 쌍을 보관합니다. |

고정한 기억을 넣는 실험은 모델이 주어진 기억을 이용하는지 살펴보기에 유용합니다. 그 결과로 검색기가 필요한 기억을 잘 찾는지 판단할 수는 없습니다. 마찬가지로 일반 장면을 고정한 평가에는 장면 분류의 오차가 들어가지 않습니다.

## Reproducible records

평가 실행부는 입력 데이터, 설정과 채점 기준의 사본 및 해시를 기록합니다. 실행에 사용한 모델 파일과 런타임 정보도 남깁니다. 파일 이름만 같고 내용이 달라진 상태를 같은 실험 조건으로 취급하지 않기 위한 장치입니다.

반복 실행의 시드도 조건에 포함됩니다. 시드는 샘플링에 쓰는 난수 설정입니다. 같은 시드를 기록했다는 사실만으로 서로 다른 기기와 런타임에서 출력이 완전히 같아진다고 보장하지는 않습니다.

평가 실행부는 응답 생성과 채점을 별도 상태로 기록합니다. 채점 단계만 실패했을 때 이미 생성한 응답을 다시 만들지 않고 재개할 수 있습니다.

## Quality and performance

품질 평가에서는 동일한 질문과 비교 조건을 사용했는지, 모든 사례의 채점이 끝났는지 확인합니다. 성능 평가에서는 모델 로드 여부와 측정 구간, 기기 상태를 추가로 확인해야 합니다.

모델이 이미 메모리에 올라온 상태의 생성 시간과 처음 모델을 로드하는 시간은 서로 다른 측정입니다. 첫 응답 시간과 답변 완료 시간도 나누어 봐야 합니다. 생성된 답변의 길이가 다르면 완료 시간 차이의 원인도 달라질 수 있습니다.

Mac에서 짧은 생성이 성공했다는 결과는 아이폰의 메모리 사용량, 장시간 사용 중 발열과 앱 전환 동작을 설명하지 않습니다. 그 항목은 실제 기기의 실행 기록이 필요합니다.
