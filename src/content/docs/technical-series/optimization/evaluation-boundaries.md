---
title: Evaluation Boundaries
description: 로컬 연구 결과와 실제 기기 동작을 구분해 기록하는 방법
---

같은 모델 파일을 사용해도 실행 환경과 입력 구성에 따라 결과가 달라질 수 있습니다. 실험의 결론을 제품에 적용하려면 무엇을 공유하고 무엇이 다른지 먼저 정리해야 합니다.

제품의 iOS·Android 경로와 Mac 평가 실행부는 Swift 입력 구성 코드를 공유합니다. 같은 코드를 호출해도 검색 자원, 문맥과 백엔드가 다르면 측정 조건도 달라집니다.

## Shared and different conditions

| 항목 | 평가 실행 조건 | 제품 경로 |
| --- | --- | --- |
| 입력 구성 | 공통 Swift 입력 구성 코드를 호출합니다. | 공통 코어에서 검색 결과와 세션 상태를 전달합니다. |
| 생성 백엔드 | 실행 설정에 지정한 백엔드를 기록합니다. | iOS는 CPU, Android는 선택한 CPU·GPU를 사용합니다. |
| 반응·배경 자료 | 고정하거나 검색을 켠 조건을 구분합니다. | 배포한 검색 자원과 문맥 범위 판정기를 사용합니다. |
| 장기 기억 | 고정 검색 결과를 주입할 수 있습니다. | SQLite에서 현재 질문과 관련 있는 기록을 검색합니다. |
| 최근 대화 | 고정 이력 또는 이어지는 다중 턴 실행을 사용합니다. | 캐릭터별 이력과 요약을 복원하고 예산에 따라 정리합니다. |

고정 기억을 넣은 결과는 모델이 그 기억을 활용하는지를 설명합니다. 필요한 기억을 찾아오는 검색 성능은 별도 결과가 필요합니다. 반응 검색과 문맥 요약도 실제로 실행한 조건에서만 품질·시간 평가에 포함됩니다.

## Reproducible records

평가 실행부는 입력 데이터, 설정과 채점 기준의 사본 및 해시를 기록합니다. 실행에 사용한 모델 파일과 런타임 정보도 남깁니다. 파일 이름만 같고 내용이 달라진 상태를 같은 실험 조건으로 취급하지 않기 위한 장치입니다.

반복 실행의 시드도 조건에 포함됩니다. 시드는 샘플링에 쓰는 난수 설정입니다. 같은 시드를 기록했다는 사실만으로 서로 다른 기기와 런타임에서 출력이 완전히 같아진다고 보장하지는 않습니다.

평가 실행부는 응답 생성과 채점을 별도 상태로 기록합니다. 채점 단계만 실패했을 때 이미 생성한 응답을 다시 만들지 않고 재개할 수 있습니다.

## Quality and performance

품질 평가에서는 동일한 질문과 비교 조건을 사용했는지, 모든 사례의 채점이 끝났는지 확인합니다. 성능 평가에서는 모델 로드 여부와 측정 구간, 기기 상태를 추가로 확인해야 합니다.

모델이 이미 메모리에 올라온 상태의 생성 시간과 처음 모델을 로드하는 시간은 서로 다른 측정입니다. 첫 응답 시간과 답변 완료 시간도 나누어 봐야 합니다. 생성된 답변의 길이가 다르면 완료 시간 차이의 원인도 달라질 수 있습니다.

실기기 자원 평가는 모델 초기화, 검색, 생성과 캐시 저장 구간을 나누어 기록합니다. 기기 메모리와 발열, 앱 전환의 영향을 비교할 때는 같은 플랫폼의 실행 기록을 사용합니다. iOS CPU의 측정값을 Android GPU의 성능으로 옮겨 해석하지 않습니다.
