---
title: Model Readiness
description: 모델 파일, 실행 메모리와 대화 자원을 준비하는 과정
---

모델 파일을 내려받은 뒤에도 바로 답변을 생성할 수 있는 것은 아닙니다. 앱은 파일 위치와 대화 자원을 확인하고, 모델 엔진과 임베딩 서비스를 초기화해야 합니다. iOS에서는 초기화에 앞서 프로세스가 사용할 수 있는 메모리 여유도 확인합니다.

## Asset and runtime state

| 단계 | 확인하거나 준비하는 것 |
| --- | --- |
| 자산 위치 확인 | 언어 모델, 임베딩 모델과 토크나이저의 위치를 가져옵니다. |
| 대화 자원 확인 | 선택한 캐릭터의 설정과 검색 인덱스, 판정기 자원을 읽습니다. |
| 모델 로드 허용 판단 | iOS는 현재 메모리 여유가 정책 기준에 도달했는지 확인합니다. |
| 언어 모델 초기화 | 모델 엔진과 대화 세션을 만들고 고정 입력의 토큰 한도를 확인합니다. |
| 문맥 복원 | 최근 대화와 저장된 요약의 호환성을 확인합니다. |
| 임베딩·라우터 준비 | 검색 모델과 도구 분류 자원을 연결합니다. |

자산 위치는 플랫폼 어댑터가 제공합니다. 공통 코어는 이 위치를 받아 초기화하므로 파일 제공 방식과 대화 처리 코드를 분리할 수 있습니다.

## Memory admission on iOS

iOS는 모델 엔진을 만들기 전에 `os_proc_available_memory()`로 현재 프로세스의 메모리 여유를 읽습니다. 제품 정책은 1GiB 이상일 때 로드를 허용합니다. 이 값은 정책상 여유 기준이며, 모델 전체 크기나 모든 기기에서 안전한 실행을 보장하는 값은 아닙니다.

기준에 미달하면 모델 준비를 보류하고 `model_memory_insufficient` 오류를 전달합니다. 저장된 대화 기록은 복원할 수 있으며, 모델 파일을 다시 선택하도록 요구하지 않습니다. 사용자가 재시도하면 운영체제 값을 다시 읽습니다. 확인한 메모리를 예약하는 기능은 아니므로 로드 이후의 사용량은 별도 관리가 필요합니다.

## Backend selection on Android

Android는 설정에 저장한 CPU 또는 GPU 선택을 초기화에 전달합니다. 네이티브 엔진의 배포 프로필이 선택한 백엔드를 지원하는지도 확인합니다. GPU 배포에는 CPU 실행도 포함되지만, CPU 전용 배포로 GPU를 요청하면 초기화를 거부합니다.

백엔드 변경은 앱 재시작 후 적용합니다. 실행 실패를 숨기기 위해 다른 백엔드로 자동 전환하지 않습니다. 캐시 호환성에도 백엔드와 엔진 식별자를 포함합니다.

## Recovery boundaries

대화 설정이나 반응 검색 자원이 없거나 잘못되면 대화 준비를 실패로 처리합니다. 도구 라우터 준비 실패는 오류를 기록한 뒤 일반 대화만 가능한 상태로 진행합니다.

모델 재준비는 저장된 대화를 유지합니다. 요약을 만든 모델과 현재 모델의 식별자가 다르면 요약을 제거하고, 남은 최근 이력으로 대화를 구성합니다. SQLite 연결도 모델 재준비와 별도로 유지합니다.

파일 준비, 모델 초기화, 실제 응답 생성은 각각 확인할 단계입니다. 모델이 준비됐다는 상태만으로 장시간 실행이나 운영체제의 메모리 회수 상황까지 검증된 것은 아닙니다.
