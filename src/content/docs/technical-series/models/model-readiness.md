모델 다운로드가 끝나도 바로 답변을 만들 수 있는 것은 아닙니다. 파일의 위치를 확인하고, 언어 모델 엔진과 임베딩 서비스를 준비한 뒤, 요청 처리에 필요한 자원까지 연결해야 합니다.

별무리 코드에서는 모델 자산을 준비하는 상태와 대화를 실행하는 런타임 상태를 따로 관리합니다. 두 상태를 구분하면 다운로드 문제와 모델 초기화 문제를 서로 다른 단계에서 살펴볼 수 있습니다.

## Asset preparation

자산은 언어 모델 팩과 메모리 모델 팩으로 나뉩니다. 메모리 모델 팩에는 임베딩 모델과 토크나이저가 포함됩니다. 현재 다운로드 순서는 메모리 팩을 먼저 준비한 뒤 언어 모델 팩을 준비하는 순서입니다.

자산 제공자는 대기, 다운로드, 확인, 준비 완료, 실패와 취소 등의 상태를 외부에 전달합니다. 전체 진행률은 두 팩의 진행률에 파일 크기 비중을 반영해 계산합니다. 작은 팩 하나가 끝났다는 이유로 전체 작업의 절반이 끝난 것으로 표시하지 않습니다.

앱의 자산 레지스트리는 준비된 파일들의 URL과 버전 정보를 보관합니다. Swift 브릿지는 이 정보를 받아 모델 초기화에 사용합니다.

## What verification means

현재 Apple 자산 제공자는 자산 관리자를 통해 파일을 열 수 있는지 검사합니다. 파일 크기나 해시를 매번 계산해 대조하지는 않습니다.

연구 실행부에는 모델 파일의 크기와 해시를 목록과 대조하는 별도 절차가 있습니다.

## Runtime preparation

| 단계 | 확인하거나 준비하는 것 |
| --- | --- |
| 자산 위치 확인 | 언어 모델, 임베딩 모델과 토크나이저의 위치를 가져옵니다. |
| 지침 자원 확인 | 대화 지침 파일과 장면 카드의 형식·체크섬을 확인합니다. |
| 언어 모델 초기화 | 모델 엔진을 생성하고 대화 설정을 준비합니다. |
| 메모리 서비스 초기화 | 임베딩 실행기와 저장·검색 구성을 준비합니다. |
| 도구 라우터 준비 | 분류기와 대표 벡터 자원을 읽습니다. |

이 단계들이 모두 같은 실패 정책을 쓰지는 않습니다. 대화 지침 자원을 확인하지 못하면 브릿지는 오류를 반환합니다. 장면 라우터 자원을 읽지 못하면 일반 장면 분류를 사용하도록 처리합니다. 도구 라우터의 자원이나 분류에 오류가 나면 해당 도구를 실행하지 않고 일반 대화 경로로 진행합니다.

따라서 준비 완료 상태 하나만으로 모든 선택 기능이 동일하게 준비되었다고 추정하면 안 됩니다. 어떤 단계에서 대체 경로가 사용되었는지는 해당 오류 기록을 함께 봐야 합니다.

## Device verification

파일이 존재하는지, 엔진 초기화가 성공했는지, 실제 답변이 생성되는지는 서로 다른 확인입니다. 다운로드 중 앱 전환, 취소 후 재시도, 앱 재실행과 저장공간 부족은 실제 기기에서 별도로 검증해야 합니다.
