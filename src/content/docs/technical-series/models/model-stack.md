별무리에서는 답변을 생성하는 일과 문장의 의미를 비교하는 일을 서로 다른 모델이 맡습니다. 현재 자산 목록에는 Gemma 4 E2B IT 언어 모델과 EmbeddingGemma 300M 임베딩 모델, 임베딩 입력을 처리할 토크나이저가 등록되어 있습니다.

언어 모델은 입력에 이어질 텍스트나 도구 호출 인자를 생성합니다. 임베딩 모델은 문장을 고정 길이의 숫자 배열로 바꿉니다. 이 배열을 벡터라고 부르며, 저장된 문장과 현재 질문의 유사도를 비교하거나 입력의 종류를 분류할 때 사용합니다.

## Responsibilities

| 작업 | 사용하는 구성 |
| --- | --- |
| 대화 답변 생성 | Gemma를 LiteRT-LM 런타임에서 실행합니다. |
| 도구 인자 생성 | 같은 언어 모델 엔진에 선택한 도구의 정의를 제공합니다. |
| 장기 기억 검색 | EmbeddingGemma가 만든 벡터의 유사도를 비교합니다. |
| 장면 선택 | 입력 벡터와 장면별 대표 벡터를 비교합니다. |
| 도구 호출 후보 판정 | 입력 벡터를 작은 신경망 분류기인 MLP에 넣습니다. |
| 도구 종류 선택 | 후보 입력의 벡터와 도구별 대표 벡터를 비교합니다. |

현재 제품 경로에서 도구 호출 여부를 판단하는 MLP는 문장을 생성하지 않습니다. 임베딩 벡터를 받아 호출 후보 여부를 점수로 계산하는 분류기입니다. 모델이 어떤 인자를 만들지 결정하는 단계는 그 이후에 실행됩니다.

## Shared embedding service

메모리 서비스가 임베딩 모델 인스턴스를 소유하며, 기억 검색과 장면·도구 분류가 이 서비스를 함께 사용합니다. 검색 대상 문장, 검색 질문, 분류 입력에는 용도에 맞는 입력 형식을 적용합니다. 같은 모델을 쓴다고 해서 모든 작업에 동일한 입력 형식을 쓰는 것은 아닙니다.

Swift 구현은 임베딩 출력의 길이가 768인지 확인하고, 유한하지 않은 숫자가 포함되면 오류로 처리합니다. 라우터 자원에도 모델 식별자와 벡터 차원에 대한 계약이 있습니다. 다른 임베딩 모델로 교체할 때는 모델 파일뿐 아니라 저장된 기억 벡터와 라우터의 대표 벡터를 함께 검토해야 합니다.

현재 임베딩 실행기는 길이 256의 입력 시퀀스를 사용하는 모델 자산에 맞춰져 있습니다. 이 값은 최근 대화를 256개 보관한다는 뜻이 아닙니다. 토크나이저가 나눈 입력 단위를 모델에 전달할 때 사용하는 길이 설정입니다.

## Shared engine, separate conversations

대화 답변과 도구 인자 생성은 로드된 언어 모델 엔진을 함께 사용합니다. 각 작업은 별도의 대화 설정을 사용합니다. 일반 대화에는 공통 지침과 장면 지침을 넣고, 도구 인자 생성에는 선택한 도구의 정의를 제공합니다.

현재 iOS 생성 런타임은 CPU 백엔드로 설정되어 있습니다. Mac 평가 실행부는 GPU를 사용하므로, 같은 모델 파일로 얻은 결과라도 두 환경의 속도를 직접 비교해서는 안 됩니다.

## Model assets

모델 자산 목록에는 파일 이름, 배포 버전, 바이트 크기와 해시가 기록되어 있습니다. 해시는 파일의 내용으로 계산한 식별값으로, 실험에 사용한 파일이 같은지 대조하는 데 쓰입니다. 모델을 바꾸고도 이전 결과와 같은 조건이라고 취급하는 일을 막으려면 실행 기록에 이 정보를 남겨야 합니다.

파일이 준비되는 과정과 모델이 실행 가능한 상태가 되는 과정은 [Model Readiness](?doc=models-model-readiness)에서 설명합니다.
