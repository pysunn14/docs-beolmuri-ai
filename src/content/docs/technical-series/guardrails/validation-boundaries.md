---
title: Validation Boundaries
description: 모델 출력이 화면·저장소·기기 기능으로 이어질 때 적용되는 검사
---

모델 출력은 여러 곳에 영향을 줍니다. 텍스트는 화면에 표시되고, 저장 판정은 기억 기록으로 이어지며, 도구 인자는 기기 기능의 실행에 사용됩니다. 각 경로에서 필요한 검사는 서로 다릅니다.

이 문서에서는 사용자 입력, 화면 표시, 기억 저장, 기기 실행으로 이어지는 지점의 검증과 상태 제어를 Guardrails라고 부릅니다. 각 검사가 어떤 오류를 막고 어디까지 확인하는지 설명합니다.

## Checks at each boundary

| 경계 | 코드가 확인하는 것 | 별도로 확인해야 하는 것 |
| --- | --- | --- |
| 사용자 입력 → 대화 요청 | 정규화한 문자열과 한국어 정규식 규칙을 대조하고, 차단한 입력은 기록·추론에 넘기지 않습니다. | 변형 표현의 누락과 정상 문장의 오탐을 확인해야 합니다. |
| 모델 출력 → 대화 화면 | 저장 판정 헤더를 분리하고 Unity 출력 필터를 적용합니다. | 답변 내용의 정확성, 적절성과 자연스러움을 평가해야 합니다. |
| 저장 판정 → 기억 기록 | 판정 형식, 표시할 답변의 존재와 요청별 저장 청구 여부를 확인합니다. | 발화가 실제로 저장할 만한 정보인지 평가해야 합니다. |
| 모델 출력 → 도구 제안 | 선택한 도구와의 일치, 필드와 자료형을 확인합니다. | 사용자의 의도에 맞는 인자인지 확인해야 합니다. |
| 제안 → 기기 실행 | 값 검증, 도구별 확인 정책과 요청 상태를 확인합니다. | 운영체제 권한과 네이티브 API의 실행 결과를 확인해야 합니다. |
| Swift 이벤트 → Unity | 요청 ID를 대조하고 완료 전에 표시 결과를 확정합니다. | 기기에서 취소와 늦은 이벤트가 어떻게 이어지는지 확인해야 합니다. |

## Input filtering

Unity의 대화 세션은 입력을 기록하거나 런타임에 보내기 전에 필터를 적용합니다. 입력과 정책 단어에 유니코드 NFKC 정규화와 소문자 변환을 적용한 뒤, 한국어는 부분 문자열로 비교하고 영어는 단어 경계를 확인합니다. 영어 경계에서 단어 문자로 취급하는 범위는 영문자, 숫자와 밑줄입니다.

정책 목록과 한국어 정규식 규칙은 JSON으로 관리합니다. 정규식은 정규화한 문자열과 원문에 적용해 자모와 변형 표현을 검사합니다. 잘못된 규칙이나 매칭 시간 초과는 필터 실패로 처리합니다. 이 검사는 문자열 규칙을 따르므로 문맥상 의도까지 판별하지는 않습니다.

## Output filtering and finalization

Unity는 스트리밍으로 모인 답변에도 같은 필터를 적용합니다. 생성 중에는 마지막 미완성 단어를 제외한 범위를 검사하고, 답변을 확정할 때 전체 텍스트를 다시 검사합니다. 출력 조각의 경계를 단어 끝으로 잘못 판단하지 않기 위한 처리입니다.

차단된 답변은 화면 기록에서 비우고 런타임에 취소를 요청합니다. 필터 실행 자체의 실패도 답변을 차단하되, 유해 표현 검출과 다른 오류 코드로 알립니다.

Swift는 완료·취소 예정 이벤트를 보낸 뒤 Unity가 확정한 표시 결과를 기다립니다. Unity는 차단한 답변을 빈 텍스트로 취소 확정합니다. 이 결과가 대화 파일에 저장되므로 차단된 답변이 다음 입력 이력에 다시 들어가지 않습니다. 생성 도중에는 확정 전 일부 텍스트가 표시될 수 있으므로 전체 답변을 받은 뒤 검사하는 방식과는 차이가 있습니다.

## Memory writes

기억을 저장하려면 출력에서 저장 대상이라는 판정값을 해석할 수 있어야 하고, 사용자에게 표시할 답변도 존재해야 합니다. 저장 대상이 아닌 판정이나 해석할 수 없는 출력에는 저장을 진행하지 않습니다.

본문이 비어 있으면 답변을 얻기 위해 한 번 재시도합니다. 저장 여부는 처음 출력의 판정과 최종 표시할 답변의 존재를 기준으로 결정하며, 재시도에서 나온 판정값은 저장 결정에 사용하지 않습니다.

요청 식별자로 저장 청구를 한 번만 허용하는 코드도 있습니다. 중복 청구를 막는 범위는 메모리에 있는 객체가 유지되는 동안이며, 재시작 이후나 저장소 차원의 중복 방지는 포함하지 않습니다.

## Tool execution

도구 경로에서는 선택된 도구, 모델이 반환한 도구 이름, 인자의 종류가 맞아야 합니다. 파서는 허용되지 않은 필드나 자료형을 거부하고, 검증기는 도구별 값의 범위를 확인합니다.

사용자 확인 후 수정한 인자도 다시 검증합니다. 실행 조정자는 도구별 확인 정책에 맞는 상태에서 실행을 허용하고, 이미 실행을 시작한 요청을 중복으로 실행하지 않습니다. 현재 시각 조회는 추가 확인을 생략합니다. 이 경로의 자세한 순서는 [Proposal and Execution](?doc=tool-use-proposal-execution)에서 설명합니다.

이 검사는 도구 호출의 형식과 값, 실행 상태를 제어합니다. 날짜나 시간의 자료형과 범위가 유효해도 사용자가 의도한 값과 다를 수 있어 해당 도구는 사용자 확인을 거칩니다. 자연어에 담긴 위험한 의도를 판별하는 기능은 이 검사에 포함되지 않습니다.

## Recalled text as input

검색한 기억은 현재 발화와 구분되는 배경 정보로 입력에 배치합니다. 입력 구성부에는 기억을 지시로 취급하지 않도록 하는 설명도 포함되어 있습니다.

기억과 지시의 구분은 모델에 전달하는 지침에 의존하므로, 외부 텍스트가 지시처럼 작동할 가능성이 남아 있습니다. 기억에 포함된 텍스트가 응답에 어떤 영향을 주는지는 별도 공격·회귀 사례로 검증해야 합니다.

## Failure policy

일반 대화와 도구 실행은 실패했을 때 다르게 처리합니다. 기억 검색에 실패하면 관련 기억 없이 답변 생성을 계속합니다. 도구 분류에서 오류가 나면 오류를 기록하고 일반 대화로 이동합니다. 도구 인자 검증에 실패하면 실행을 진행하지 않습니다.

현재 코드의 오류 코드와 단계별 기록으로 어떤 단계에서 실패했는지 확인할 수 있습니다. 운영 중 오류 탐지와 대응이 충분한지는 별도로 평가해야 합니다.

## Implementation references

입력 필터는 공개 AI 저장소에 포함되지 않은 Unity 구현입니다. 앱 저장소에서 다음 경로로 적용 위치와 테스트를 확인할 수 있습니다.

- `unity/Assets/PetAI/Scripts/Application/Chat/ChatInputFilter.cs`: 정규화와 매칭
- `unity/Assets/PetAI/Scripts/Application/Chat/ChatSession.cs`: 기록·추론 전 검사
- `unity/Assets/PetAI/Scripts/Application/Chat/ChatSession.OutputFilter.cs`: 출력 차단
- `unity/Assets/PetAI/Scripts/Application/Chat/ChatSession.TurnFinalization.cs`: 표시 결과 확정
- `unity/Assets/PetAI/Tests/EditMode/Chat/ChatInputFilterTests.cs`: 정책 로딩과 매칭 테스트

기억 저장의 트랜잭션과 실패 주입 검증은 [What gets saved](?doc=memory-save)에서 설명합니다.
