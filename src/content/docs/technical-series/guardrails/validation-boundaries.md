---
title: Validation Boundaries
description: 모델 출력이 화면·저장소·기기 기능으로 이어질 때 적용되는 검사
---

모델 출력은 여러 곳에 영향을 줍니다. 텍스트는 화면에 표시되고, 저장 판정은 기억 기록으로 이어지며, 도구 인자는 기기 기능의 실행에 사용됩니다. 각 경로에서 필요한 검사는 서로 다릅니다.

여기서 Guardrails는 사용자 입력, 화면 표시, 기억 저장, 기기 실행으로 이어지는 지점의 검증과 상태 제어를 뜻합니다.

## Checks at each boundary

| 경계 | 코드가 확인하는 것 | 별도로 확인해야 하는 것 |
| --- | --- | --- |
| 사용자 입력 → 대화 요청 | 정적 필터 목록과 대조하고, 차단한 입력은 기록·추론에 넘기지 않습니다. | 변형 표현의 누락과 정상 문장의 오탐을 확인해야 합니다. |
| 모델 출력 → 대화 화면 | 저장 판정에 해당하는 제어 부분을 분리합니다. | 답변 내용의 정확성, 적절성과 자연스러움을 평가해야 합니다. |
| 저장 판정 → 기억 기록 | 판정 형식, 표시할 답변의 존재와 요청별 저장 청구 여부를 확인합니다. | 발화가 실제로 저장할 만한 정보인지 평가해야 합니다. |
| 모델 출력 → 도구 제안 | 선택한 도구와의 일치, 필드와 자료형을 확인합니다. | 사용자의 의도에 맞는 인자인지 확인해야 합니다. |
| 제안 → 기기 실행 | 값 검증, 사용자 승인과 요청 상태를 확인합니다. | 운영체제 권한과 네이티브 API의 실행 결과를 확인해야 합니다. |
| Swift 이벤트 → Unity | 현재 요청과 이벤트의 식별자를 대조합니다. | 기기에서 취소와 늦은 이벤트가 어떻게 이어지는지 확인해야 합니다. |

## Input filtering

Unity의 대화 세션은 입력을 기록하거나 런타임에 보내기 전에 필터를 적용합니다. 입력과 정책 단어에 유니코드 NFKC 정규화와 소문자 변환을 적용한 뒤, 한국어는 부분 문자열로 비교하고 영어는 단어 경계를 확인합니다. 영어 경계에서 단어 문자로 취급하는 범위는 영문자, 숫자와 밑줄입니다.

정책 목록은 코드와 분리된 JSON으로 관리합니다. 목록 원문은 공개하지 않으며, 이 문서는 적용 방식과 한계만 설명합니다. 현재 정규화는 단어 사이의 숫자·기호 삽입이나 발음 치환을 모두 복원하지 않습니다. 정적 목록이 자연어의 의도나 문맥을 판별하는 것도 아닙니다.

이 필터는 사용자 입력에 적용됩니다. 모델 답변의 유해 표현을 차단하는 출력 필터는 연결되어 있지 않습니다. 아래의 출력 제어 부분 분리는 유해 표현 검사와 별개입니다.

## Memory writes

기억 저장은 모델이 판정값을 출력했다는 사실만으로 수행되지 않습니다. 출력에서 판정값을 해석할 수 있어야 하고, 사용자에게 표시할 답변도 존재해야 합니다. 저장 대상이 아닌 판정이나 해석할 수 없는 출력에는 저장을 진행하지 않습니다.

본문이 비어 있을 때 한 번 재시도하는 처리는 답변을 얻기 위한 것입니다. 재시도의 판정값을 이용해 처음의 불명확한 저장 결정을 새로 확정하는 구조는 아닙니다. 저장 여부는 처음 출력의 판정과 최종 표시할 답변의 존재를 기준으로 결정합니다.

요청 식별자로 저장 청구를 한 번만 허용하는 코드도 있습니다. 이 방어 코드의 수명은 메모리에 있는 객체의 수명과 같습니다. 재시작이나 저장소 차원의 중복까지 같은 보증으로 설명하지 않습니다.

## Tool execution

도구 경로에서는 선택된 도구, 모델이 반환한 도구 이름, 인자의 종류가 맞아야 합니다. 파서는 허용되지 않은 필드나 자료형을 거부하고, 검증기는 도구별 값의 범위를 확인합니다.

사용자 확인 후 수정한 인자도 다시 검증합니다. 실행 조정자는 확인 대기 상태에서만 실행을 허용하고, 이미 실행을 시작한 요청을 중복으로 실행하지 않습니다. 이 경로의 자세한 순서는 [Proposal and Execution](?doc=tool-use-proposal-execution)에서 설명합니다.

이 검사는 정의된 도구 호출 경로를 제어합니다. 자연어로 표현된 모든 위험한 의도를 판별하는 분류기라고 볼 수는 없습니다. 자료형과 범위가 유효해도 사용자가 의도한 값과 다를 수 있습니다.

## Recalled text as input

검색한 기억은 현재 발화와 구분되는 배경 정보로 입력에 배치합니다. 입력 구성부에는 기억을 지시로 취급하지 않도록 하는 설명도 포함되어 있습니다.

이 구분은 모델에 전달하는 지침입니다. 외부 텍스트가 지시처럼 작동하는 문제를 코드 수준에서 완전히 차단했다는 보장은 아닙니다. 기억에 포함된 텍스트가 응답에 어떤 영향을 주는지는 별도 공격·회귀 사례로 검증해야 합니다.

## Failure policy

일반 대화와 도구 실행은 실패했을 때 다르게 처리합니다. 기억 검색에 실패하면 관련 기억 없이 답변 생성을 계속합니다. 도구 분류에서 오류가 나면 오류를 기록하고 일반 대화로 이동합니다. 도구 인자 검증에 실패하면 실행을 진행하지 않습니다.

모든 실패를 같은 오류 하나로 모으면 어떤 기능이 생략됐는지 알기 어렵습니다. 현재 코드의 오류 코드와 단계별 기록은 이런 차이를 살펴보는 근거입니다. 로그가 존재한다는 사실과 운영 중 오류를 충분히 탐지하고 대응할 수 있다는 평가는 구분해야 합니다.

## Implementation references

입력 필터는 공개 AI 저장소에 포함되지 않은 Unity 구현입니다. 앱 저장소에서 다음 경로로 적용 위치와 테스트를 확인할 수 있습니다.

- `unity/Assets/PetAI/Scripts/Application/Chat/ChatInputFilter.cs`: 정규화와 매칭
- `unity/Assets/PetAI/Scripts/Application/Chat/ChatSession.cs`: 기록·추론 전 검사
- `unity/Assets/PetAI/Tests/EditMode/Chat/ChatInputFilterTests.cs`: 정책 로딩과 매칭 테스트

기억 저장의 트랜잭션과 실패 주입 검증은 [What gets saved](?doc=memory-save)에서 설명합니다.
