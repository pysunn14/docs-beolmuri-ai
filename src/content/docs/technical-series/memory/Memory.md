---

별무리의 대화 입력에는 최근 대화와 검색한 장기 기억이 함께 들어갑니다. 최근 대화는 이어지는 문맥을 제공하고, 장기 기억은 저장된 발화 중 현재 질문과 관련 있는 내용을 제공합니다.

## Two kinds of context

| 구분 | 최근 대화 | 장기 기억 |
| --- | --- | --- |
| 보관 위치 | Swift가 관리하고 기기 내 JSON 파일에 보존합니다. | SQLite에 기록합니다. |
| 포함 대상 | 사용자 발화, 표시한 답변과 요청 상태, 대화로 가져온 홈 대사입니다. | 완료된 일반 대화에서 P·E 저장 판정을 통과한 사용자 발화입니다. |
| 선택 기준 | 현재 요청을 포함해 최근 항목 20개를 유지합니다. | 최근 문맥에 없는 기억 중 현재 질문과 관련 있는 내용을 검색합니다. |
| 수명 | 범위를 벗어난 항목은 모델의 최근 문맥에서 제거합니다. | 최근 문맥에서 빠져도 저장된 활성 기억은 검색할 수 있습니다. |

최근 문맥의 제한은 화면에서 스크롤해 읽는 기록의 제한과 다릅니다. 장기 기억에 저장되지 않은 발화가 최근 문맥에서 빠지면, 화면 기록에 남아 있어도 장기 기억 검색으로 가져올 수 없습니다.

## Recent context lifecycle

사용자 발화는 요청을 받아들일 때 파일에 저장합니다. 저장이 실패하면 생성을 시작하지 않습니다. 답변 조각은 생성 중 메모리에 반영하고, 완료·취소·오류 때 최종 상태와 함께 파일에 저장합니다. 정상적으로 취소를 처리했다면 그때까지 표시한 부분 답변도 남습니다.

생성 중인 조각마다 파일을 갱신하지는 않습니다. 앱이 갑자기 종료되면 마지막 저장 이후에 표시한 부분 답변은 복원되지 않을 수 있습니다. 시작할 때 저장한 사용자 발화는 남으며, 끝나지 않은 요청은 취소 상태로 복원합니다. 정상 종료 알림에 의존하지 않도록 파일은 원자적으로 교체합니다.

홈 대사는 사용자 입력이 없는 별도 항목으로 보관하며, 같은 최근 문맥의 개수 제한을 사용합니다. 최근 대화 파일은 기기 단위이며 로그인 계정에 따라 파일을 바꾸지 않습니다.

## Long-term memory lifecycle

답변 완료와 장기 기억 저장 완료는 서로 다릅니다. 일반 대화는 답변 처리를 끝낸 뒤 저장 대상 발화의 임베딩을 준비하고, 관련 행을 하나의 SQLite 트랜잭션으로 기록합니다. 저장 실패가 이미 표시한 답변을 지우지는 않습니다.

취소·오류 요청과 저장 대상이 아닌 판정은 일반 대화의 장기 기억 저장으로 이어지지 않습니다. 도구 경로도 이 저장 절차를 거치지 않습니다. 판정 기준, 원문 저장 범위와 실패 처리는 [What gets saved](?doc=memory-save)에서 설명합니다.

## Retrieval boundary

새 요청이 들어오면 먼저 최근 문맥의 범위를 갱신합니다. 일반 대화 1~20번이 있는 상태에서 21번을 시작하면, 이전 문맥은 2~20번이고 현재 질문은 21번입니다. 검색에서는 이 범위의 요청 ID를 제외하므로, 장기 기억으로 저장된 1번은 다시 검색 후보가 될 수 있습니다.

이 기준은 같은 발화가 최근 문맥과 검색 기억에 함께 들어가는 일을 막습니다. 문구가 같은 검색 결과를 합치는 중복 제거와는 별개입니다. 순위 계산, 입력 예산과 검색의 한계는 [How memories are retrieved](?doc=memory-retrieval)에서 설명합니다.
