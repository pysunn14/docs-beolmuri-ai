title: Request Routing
description: 일반 대화와 기기 기능 요청을 나누는 두 단계 분류
---

도구 라우팅은 발화가 기기 기능의 실행을 요구하는지, 요구한다면 어느 기능에 해당하는지 판단하는 과정입니다. 일상적인 대화에 기능과 관련된 단어가 나온다는 이유만으로 실행 제안을 만들면 불필요한 확인 화면이 나타날 수 있습니다.

현재 제품 경로는 먼저 실행 요청 후보인지를 판단하고, 그 결과가 후보일 때 도구의 종류를 선택합니다. 두 단계는 하나의 임베딩 벡터를 함께 사용합니다.

## Actionability

입력을 임베딩 모델에 넣으면 768개 값으로 이루어진 벡터가 나옵니다. 작은 신경망 분류기인 MLP는 이 벡터를 입력으로 받아 도구 호출 후보 점수를 계산합니다. 설정된 임계값 이상이면 다음 단계로 보내고, 그보다 낮으면 일반 대화로 분류합니다.

이 단계는 실행에 필요한 날짜나 수량 같은 인자를 생성하지 않습니다. 해당 발화를 도구 선택 단계까지 보낼지 결정합니다. 분류기의 가중치와 임계값은 별도 자원에 담겨 있으며, 로딩할 때 벡터 차원과 자원 형식을 검사합니다.

점수는 호출 후보를 구분하는 데 쓰입니다. 그 값을 그대로 사용자 요청을 올바르게 이해했을 확률로 해석하려면 별도의 보정과 검증이 필요합니다.

## Tool selection

두 번째 단계는 입력 벡터와 도구별 대표 벡터를 비교합니다. 각 도구에서 가장 높은 유사도를 구하고 도구별 임계값과 대조합니다.

| 기준을 넘은 도구 수 | 처리 |
| --- | --- |
| 0개 | 일반 대화로 진행합니다. |
| 1개 | 해당 도구를 선택합니다. |
| 2개 이상 | 충돌로 분류하고 요청을 나누도록 안내합니다. |

이 규칙은 [Scene Routing](?doc=dialogue-scene-routing)의 장면 선택과 다릅니다. 장면 라우터는 여러 합격 후보 중 하나를 고르지만, 도구 선택기는 여러 후보를 충돌로 처리합니다. 여러 기능을 한 요청에서 순서대로 실행하는 계획을 만드는 구조는 아닙니다.

## Availability and clarification

도구가 하나 선택되어도 바로 인자를 생성하지 않습니다. 현재 세션에서 허용된 도구 목록에 있는지 먼저 확인합니다. 허용되지 않은 도구라면 해당 상태를 반환합니다.

일부 요청에는 추가 확인 절차가 있습니다. 현재 코드에는 로컬 알림 요청의 필수 정보가 부족한 경우 명확히 해 달라고 안내하는 처리가 연결되어 있습니다. 이 처리가 모든 도구의 모호한 요청을 일반적으로 해결한다고 볼 수는 없습니다.

이후 언어 모델이 선택한 도구의 인자를 생성합니다. 모델에는 그 도구의 정의를 제공하며, 반환한 도구 이름이 선택한 도구와 일치하는지도 검사합니다.

## Failure behavior

임베딩을 만들지 못하거나 도구 라우팅 자원에 문제가 있으면 브릿지는 오류를 기록하고 일반 대화 경로로 진행합니다. 이때 기기 기능을 실행하지는 않습니다. 다만 실행 요청이 일반 대화 응답으로 처리될 수 있으므로, 라우터 오류와 정상적인 일반 대화 판정을 진단 기록에서 구분해야 합니다.
