## Evaluation Setup


호출 판별기의 비교 실험은 실제 요청 168건과 일반 대화 24건으로 구성된 기존 평가셋을 사용했습니다. 비실행 사례만 보강한 조건과, 같은 기능의 실행·비실행 사례를 함께 보강한 조건을 비교했습니다. 평가 문장과 완전히 겹치는 학습 후보 3건은 제외했습니다.

| 학습 구성 | 일반 대화의 잘못된 호출 후보 판정 | 실제 요청 재현율 | 호출 여부 분류 정확도 |
| --- | --- | --- | --- |
| 초기 3i4K 기반 MLP | 16/24 (66.67%) | 163/168 (97.02%) | 89.06% |
| 한국어 비실행 사례 보강 | 2/24 (8.33%) | 118/168 (70.24%) | 72.92% |
| 기능별 실행·비실행 사례를 함께 보강 | 2/24 (8.33%) | 160/168 (95.24%) | 94.79% |
| 위 구성에 한국어 비실행 사례 추가 | 1/24 (4.17%) | 159/168 (94.64%) | 94.79% |

비실행 사례만 보강한 조건은 잘못된 호출을 줄이면서 정상 요청도 많이 거절했습니다. 기능별 실행·비실행 사례를 함께 보강한 두 조건은 전체 정답 수가 같지만 오류 구성이 다릅니다. 마지막 조건은 잘못된 호출을 한 건 줄이는 대신 정상 요청을 한 건 더 놓쳤습니다.

임베딩 기준선의 일반 대화 오활성은 11/24(45.83%)였으며, 마지막 MLP 후보는 1/24(4.17%)였습니다. 두 값은 호출 후보 판정 결과입니다. 인자 생성과 사용자 확인 이후의 실제 기능 실행 성공률을 측정한 값은 아닙니다.

이 평가는 개발 중 이미 열람한 Holdout을 재사용한 회고 비교입니다. Dev와 Holdout 사이에도 같은 문장 8건이 있으므로 두 점수를 독립적인 검증 결과로 취급하지 않습니다.
