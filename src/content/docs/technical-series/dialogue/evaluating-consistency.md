---
title: Evaluating Consistency
description: 대화의 일관성을 비교하는 평가 구조와 해석 범위
---

대화가 자연스러운지 판단하려면 여러 항목을 살펴봐야 합니다. 앞선 대화와 모순되는지, 설정을 유지하는지, 질문에 맞게 답하는지는 서로 다른 평가입니다. 하나의 점수로 합치면 어떤 문제가 줄고 어떤 문제가 늘었는지 알기 어렵습니다.

현재 평가 도구는 그중 정체성 유지의 한 부분을 다룹니다. 설정과 어긋나는 호칭이 주어졌을 때 응답이 설정을 유지하는지, 올바른 호칭에도 불필요한 정정을 하는지 짝을 지어 비교합니다.

## Paired inputs

문제 입력만 평가하면 정정을 자주 하는 응답이 좋은 결과처럼 보일 수 있습니다. 그래서 각 문제 입력에 정상적인 대조 입력을 함께 둡니다. 하나의 오류를 줄이는 설정이 정상 입력에 새로운 오류를 만드는지도 확인하기 위한 구성입니다.

결과는 다음처럼 나누어 집계합니다.

| 대상 | 관찰하는 결과 |
| --- | --- |
| 설정과 어긋나는 입력 | 설정을 유지했는지, 잘못된 설정을 받아들였는지, 불일치를 처리하지 않았는지 구분합니다. |
| 정상 대조 입력 | 필요하지 않은 정정을 했는지 확인합니다. |
| 판정하기 어려운 응답 | 별도 범주로 남기고 비율 계산에서 숨기지 않습니다. |
| 실행 실패 | 응답 생성 실패와 채점 실패를 구분해 집계합니다. |

평가 도구는 채점이 끝난 응답의 비율과 전체 예정 작업 중 채점을 완료한 비율을 함께 기록합니다. 일부 사례에서 생성이나 채점이 실패했다면, 완료된 일부의 높은 점수만으로 전체 품질을 주장할 수 없습니다.

## Shared input construction

평가 실행부는 Swift의 입력 구성 코드를 호출합니다. 공통 지침과 장면 지침, 세션 정보, 일관성 지침과 기억 판정을 설정별로 포함하거나 제외할 수 있습니다. Python에서 제품의 입력 조합 규칙을 따로 복제하는 범위를 줄이는 구조입니다.

평가 실행부에서는 고정된 최근 대화와 기억을 주입하거나, 지침을 배치하는 위치를 바꿀 수 있습니다. 이때 고정 기억은 이미 검색되었다고 가정한 입력입니다. 실제 저장소에서 적절한 기억을 찾아오는 검색 성능까지 평가하는 것은 아닙니다.

또한 평가의 장면은 일반 분류로 고정되어 있습니다. 이 결과에는 실제 장면 라우터가 어떤 지침을 선택했는지에 따른 오차가 포함되지 않습니다.

## Grading

응답의 의미를 판단하는 채점 단계는 외부 모델을 호출합니다. 앱의 온디바이스 생성 경로와 구분되는 연구용 경로이며, 합성 평가 입력과 생성 응답을 사용합니다.

채점기에는 기준과 평가 대상 응답을 전달합니다. 비교 중인 설정의 이름이나 변경 의도를 전달하는 대신 응답 자체를 판정하도록 구성되어 있습니다. 채점 결과는 정해진 형식을 통과해야 하며, 근거로 제시한 문자열이 실제 응답에 존재하는지도 검사합니다.

이 검사가 채점기의 의미 판단까지 보증하지는 않습니다. 판정 기준이 애매한 사례와 개선·악화로 분류된 사례는 사람이 함께 검토할 대상으로 남습니다.

## Comparing runs

비교 실행부는 데이터와 모델 파일, 반복 조건, 런타임, 채점 설정이 맞는지 확인합니다. 비교할 모든 사례의 채점이 끝나야 결과를 비교할 수 있습니다. 전체 비율 차이와 함께 같은 사례에서 성공이 실패로 바뀌었는지, 실패가 성공으로 바뀌었는지도 계산합니다.

말투의 자연스러움, 반복, 질문에 대한 적절성, 장기간의 문맥 유지는 이 평가의 대상이 아닙니다.
