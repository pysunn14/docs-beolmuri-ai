---
title: Evaluating Consistency
description: 대화의 일관성을 비교하는 평가 구조와 해석 범위
---

호칭 일관성 평가는 설정과 어긋나는 호칭에도 응답이 정체성을 유지하는지, 올바른 호칭에는 불필요한 정정을 하는지 짝을 지어 비교합니다. 두 결과를 나누어 보면 잘못된 호칭을 거부하도록 만든 지침이 정상 대화에도 영향을 주는지 알 수 있습니다.

앞선 대화와의 모순, 질문에 대한 적절성과 정체성 유지는 서로 다른 평가 항목입니다. 이 문서는 그중 호칭에 대한 정체성 유지 평가를 설명합니다.

## Paired inputs

문제 입력만 평가하면 정정을 자주 하는 응답이 좋은 결과처럼 보일 수 있습니다. 그래서 각 문제 입력에 정상적인 대조 입력을 함께 둡니다. 하나의 오류를 줄이는 설정이 정상 입력에 새로운 오류를 만드는지도 확인하기 위한 구성입니다.

결과는 다음처럼 나누어 집계합니다.

| 대상 | 관찰하는 결과 |
| --- | --- |
| 설정과 어긋나는 입력 | 설정을 유지했는지, 잘못된 설정을 받아들였는지, 불일치를 처리하지 않았는지 구분합니다. |
| 정상 대조 입력 | 필요하지 않은 정정을 했는지 확인합니다. |
| 판정하기 어려운 응답 | 별도 범주로 남기고 비율 계산에서 숨기지 않습니다. |
| 실행 실패 | 응답 생성 실패와 채점 실패를 구분해 집계합니다. |

평가 도구는 채점이 끝난 응답의 비율과 전체 예정 작업 중 채점을 완료한 비율을 함께 기록합니다. 생성이나 채점에 실패한 사례가 있으면 이 완료율을 통해 결과가 전체 예정 작업 중 어느 범위를 다루는지 확인할 수 있습니다.

## Shared input construction

평가 실행부는 Swift의 입력 구성 코드를 호출합니다. 고정 지침, 세션 정보, 일관성 지침과 기억 판정 등을 조건별로 구성할 수 있습니다. Python에서 제품의 입력 조합 규칙을 따로 복제하는 범위를 줄이는 구조입니다.

평가 실행부에서는 고정된 최근 대화와 기억을 주입하거나, 지침을 배치하는 위치를 바꿀 수 있습니다. 이 문서에서 다루는 고정 입력 비교는 문맥을 정해 두고 지침 설정에 따른 응답 차이를 측정합니다. 제품의 반응 자료 검색을 평가하려면 검색 입력, 인덱스와 판정기 설정을 별도 조건으로 포함해야 합니다.

## Grading

응답의 의미를 판단하는 채점 단계는 외부 모델을 호출합니다. 앱의 온디바이스 생성 경로와 구분되는 연구용 경로이며, 합성 평가 입력과 생성 응답을 사용합니다.

채점기에는 기준과 평가 대상 응답을 전달합니다. 비교 중인 설정의 이름이나 변경 의도를 전달하는 대신 응답 자체를 판정하도록 구성되어 있습니다. 채점 결과는 정해진 형식을 통과해야 하며, 근거로 제시한 문자열이 실제 응답에 존재하는지도 검사합니다.

형식과 근거 문자열 검사에 더해, 판정 기준이 애매한 사례와 개선·악화로 분류된 사례는 사람이 의미 판단을 검토할 대상으로 남습니다.

## Comparing runs

비교 실행부는 데이터와 모델 파일, 반복 조건, 런타임, 채점 설정이 맞는지 확인합니다. 비교할 모든 사례의 채점이 끝나야 결과를 비교할 수 있습니다. 전체 비율 차이와 함께 같은 사례에서 성공이 실패로 바뀌었는지, 실패가 성공으로 바뀌었는지도 계산합니다.

고정 기억은 이미 검색되었다고 가정한 입력입니다. 실제 저장소에서 적절한 기억을 찾아오는 검색 성능은 평가하지 않습니다. 반응 검색이나 문맥 요약을 실행하지 않은 조건에는 그 단계의 오류와 비용이 포함되지 않습니다.

말투의 자연스러움, 반복, 질문에 대한 적절성, 장기간의 문맥 유지는 이 평가의 대상이 아닙니다.
